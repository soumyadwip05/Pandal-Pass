# commit.md - Commit policy

PandalPass work must be committed in logical parts. Do not put the whole project into one commit.

## Command

From the repository root:

```bash
bash commit.js
```

Preview without committing:

```bash
bash commit.js --dry-run
```

`commit.js` is a bash script despite the `.js` extension. It is not run with Node.js. On Windows, run it from Git Bash, where `bash` is available.

## What the script does

- Finds the repository root.
- Refuses to run when changes are already staged.
- Checks each known file group.
- Skips groups with no changes.
- Stages only the files in that group.
- Creates one commit per group with a plain message.
- Never pushes, amends, rebases or force-pushes.
- Prints remaining changed files at the end so nothing is silently forgotten.

The `legacy/` archive gets one group for its initial move. Reference apps, images and the retired seed are otherwise not edited or recommitted.

| Project documentation | `docs: document the project and Next.js migration plan` |

Adjust the script if the final folder structure differs, but keep the same principle: one logical part per commit.

## Message rules

Commit subjects and descriptions must be plain and simple.

Allowed:

```text
feat: build planner summary
fix: preserve planner state after navigation
docs: add local setup notes
```

Not allowed:

- Emojis.
- AI, bot, model or assistant names.
- `Generated by`, `Co-authored-by` or tool signatures unless the user explicitly asks.
- Watermarks or promotional trailers.
- Vague messages such as `updates`, `stuff` or `final`.
- Mixing unrelated parts in one commit.

Keep the subject imperative, lowercase after the type prefix and under about 72 characters. Add a short body only when the reason for the change is not obvious. The body must also be plain text.

## Safety rules

- Never stage `.env` files, secrets, credentials, API keys or local machine settings.
- Never commit build output, `.next/`, `node_modules/` or temporary screenshots.
- Never edit or recommit the files inside `legacy/`; only the archive move itself is committed.
- Do not commit unless the user asks for commits.
- If a group fails, fix the problem and rerun the script. It is safe to rerun because empty groups are skipped.
- Do not squash or rewrite published history.

## After the script

The script prints the remaining working tree status. Review it before doing anything else. If files remain, decide whether they belong to an existing group or need a new, clearly named group in `commit.js`.
